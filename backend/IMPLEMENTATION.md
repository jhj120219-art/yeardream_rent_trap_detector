## 파일 수신 후 바로 시작하기 위한 설계 — 실행 전

사용자 요청에 따라 이번 단계는 설계만 진행한다. 아래 절차는 아직 구현/실행 완료가 아니며, 실제 CSV 교체·외부 API 호출·분석 정책 전환·배포는 하지 않는다.

### 쉬운 설명

거래 파일 받기 → 파일이 맞는지 검사 → 시험용 서버에 연결 → 직접 입력해 계산 확인 → 이상 없을 때 실제 연결. 문제가 있으면 기존 파일과 저장된 매물은 그대로 둔다. 사용자에게 필요한 것은 파일을 받아 저장하는 일이며, 검사와 연결 작업은 백엔드 담당이 한다.

### 2. 수신·검사 설계

### 4. 실제 적용과 되돌리기 설계

- 검증한 스냅샷은 backend/data/snapshots/의 별도 파일로 보존하고 RENT_CLEAN_CSV로 선택하는 방식을 우선한다. 기존 기본 경로 사용이 필요하면 검증 완료 후 같은 파일시스템의 임시 파일에서 원자 교체하도록 후속 구현한다. 자동 교체 기능이 현재 구현됐다는 뜻은 아니다.
- 데이터는 서버 시작 시 읽으므로 적용 시 서버 재시작이 필요하다. 이전 스냅샷 경로를 기록하고 적용 후 READY와 대표 요청을 다시 확인한다.
- 실패하면 이전 경로로 복귀해 재시작한다. 최초 연결이라 이전 데이터가 없으면 MISSING 상태를 유지한다. 사용자 매물 DB·과거 분석 결과는 삭제하지 않는다.
- 과거 분석은 저장된 당시 결과를 유지한다. 재분석은 새 분석 결과로 저장한다. 후속 구현에서는 데이터 스냅샷 해시·분석 버전을 결과 바깥의 메타데이터에 기록하는 안을 검토하며 기존 result 계약을 임의 변경하지 않는다.
- 공개 Git에는 코드·익명/가상 예시·일반 진행 기록만 명시적으로 stage한다. CSV·키·DB·개별 거래가 담긴 검사 결과는 제외한다.

### 5. 주소·캡처의 후속 설계
