## 기획 차이 및 분석 협의안

회의는 같은 건물 → 주변 유사 건물. 현재 분석은 법정동 → 조건 완화 → 같은 구 전체. 건물동·호수는 보관만 하며 동일 건물/호실을 식별하지 않는다.

reference.conditions, relaxed_conditions, sample_count와 가격 통계는 존재하지만 개별 거래 목록은 없다. Pool에는 선별용 배열만 있고 거래·건물 식별 계약이 없다. 백엔드에서 별도 필터로 목록을 추정하면 통계 표본과 달라질 수 있으므로 만들지 않았다.

분석 담당 제안(미확정): 최종 선별 표본을 `comparables`로 반환하고 공개 필드·익명화·최대 개수·전체 건수·정렬 기준을 합의한다. 출력 제안 예: `{comparables:[{contract_date:"2026-09-01",area_m2:59.9,deposit_10k_krw:5000,rent_10k_krw:50}],total_count:40,returned_count:1}`. 현재 API 응답이 아니다. 환산 월세가 필요하면 분석 함수의 기존 계산 결과를 반환해야 한다. 원자료 재배포 조건 확인도 필요하다.

영향: 분석 계약 버전·로딩·결과 스냅샷·프론트 목록 UI 변경. 백엔드는 승인된 분석 출력을 result에 그대로 저장/반환하는 구조 유지. 별도 가격 계산 없음.

정책 지원 지역은 관악·광진·마포·동작·강서·노원이다. 아파트·오피스텔·연립다세대 등 기존 유형/별칭만 사용한다. 빌라의 실제 유형 확인 필요. 실제 지원 표시는 /capabilities.loaded_coverage로 확인하며 현재 운영 데이터는 미연결이다. 관리비·주차·엘리베이터는 가격과 분리한다. 기존 confidence_details를 정확도·사기 확률·새 유사도 %로 표시하지 않는다.
