선택 전 초안: 서로 다른 관리비 기준·지원 범위·주소 입력 방식·거래 목록 범위는 아래 결정표에서 선택을 기다립니다. 결론을 임의로 확정하거나 실행 코드를 변경하지 않았습니다.
월세 분석 연결과 관리비 입력 저장 코드는 있습니다.
집 서버의 최신 버전 적용·실제 프론트 화면 검증·관리비 추정 계산 연결은 남았습니다. 아래 그림은 구현을 제안하는 시안입니다.

토스: 쉬운 돈 설명 / 당근: 동네 중심 / 오늘의집: 사진에서 정보 확인. 색상·로고를 복제하지 않고 정보 순서와 사용 흐름을 참고합니다.

01. 정의서에 맞춘 4단계 화면

1. 입력 방식

어떤 방법으로 입력할까요?

광고 캡처 올리기 / 주소 검색 / 직접 입력

요구사항 003~005

직접 입력도 주소 검색을 사용한다는 정의서와 현재 API의 직접 입력 대체 방식을 별도 확인

2. 정보 가져오기

찾아온 정보를 확인해요

주소 선택 → 건물 조회 / 캡처 → 정보 추출. 이 화면은 읽기 전용. 각 값 옆에 출처 표시

요구사항 006~008

호실 면적·현재 월세를 건물 전체 정보나 과거 거래로 자동 채우지 않기. 건축물대장 자동 조회는 추가 연결 필요

3. 입력·확인

내 매물 정보가 맞나요?

주소·유형·면적과 기준·보증금·월세·관리비·건축연도·층 수정 → 최종 확인

요구사항 009~021

주소 변경 시 건물 조회값만 갱신. 기존 직접 입력·캡처값 보존 후 재확인. 값 변경 시 확인 해제. 관리비는 5항목 체크 + 총액만 입력

4. 결과

내 월세는 기준과 얼마나 다를까요?

입력 70만원 / 기준 60만원 → 월 10만원·16.7% 높아요. 그 아래 범위·조건·기간·건수·신뢰도·출처

요구사항 022~035

비교 완료일 때 높음 빨강·낮음 파랑. 참고용은 중립색 수치+사유, 높다/낮다 판정 없음. 관리비 비용은 별도 영역·선택 대기

가독성: 진한 본문, 한 화면 한 가지 주요 행동, 차액·퍼센트를 결과 첫 화면에 표시. 높음은 빨강·낮음은 파랑이며 비교 완료 상태에만 적용. 참고용은 중립색·사유 우선.

02. 최종 큰 그림 — 누가 무엇을 하나요?

화면 검증 필요① 프론트캡처·주소 검색·직접 입력주소·유형·면적·금액 수정
코드 검증② 백엔드입력 검증·사용자 확인DB에 원문·항목별 저장
월세 연결 확인③ 분석가 코드동네 유사 거래 비교우리 서버가 코드 실행. 별도 분석가 서버 응답 방식 아님
코드 검증④ 백엔드결과 저장·보고서 조합관리비 입력과 월세 결과 구분
실제 화면 미확인⑤ 프론트범위·차이·근거 표시소비자가 조건과 한계 확인

월세 흐름

실거래 CSV → 분석가의 비교 코드 → 백엔드 호출 → DB 결과 저장 → 프론트 출력

로컬·기존 집 API 흐름 확인

같은 건물 우선은 현재 운영 범위에서 끔. 동네 비교 유지.

관리비 흐름

광고 명시값: 프론트 입력 → 백엔드 5항목 저장 → 화면 표시

참고 비용: 사용량 CSV + 분석가 계산 코드 → 백엔드 연결 → 결과 표시

CSV 확보·단위/출력 계약·연결 검증 필요

서버 운영은 별도 길입니다. Git push/pull은 코드를 옮깁니다. 집 DB·환경설정은 자동 이동하지 않습니다. 집 Tailscale·SSH 연결 후 백업 → 최신 코드 반영 → 서버 재시작 → 확인해야 합니다.
