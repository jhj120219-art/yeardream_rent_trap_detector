# 팀 이미지 판독 업데이트 연결 — 2026-10-22

팀 새 브랜치 feat/extraction-consensus (원본 872973b, 분석 모듈 bf8c39d)를 확인했습니다. 아직 main에 병합되지 않은 작업입니다. 팀의 분석·프론트 파일을 임의 수정하지 않았습니다. 개인 저장소에는 분석가 consensus.py를 원본 그대로 통합했으며 계산 규칙은 바꾸지 않았습니다.

## 무엇이 추가됐나요?
- 기존 POST /extraction/card-consensus: 엔진별 판독 결과를 받아 같은 값만 입력 후보로 반환합니다. 저장하지 않습니다.
- 새 POST /extractions/card-consensus: 같은 요청에 card_index(0부터 시작)를 추가하면 합의된 월세 카드 하나를 extraction으로 저장합니다.
- GET /extractions/{id}/listing-draft: 기존 확인용 입력 후보로 연결합니다. 사용자 확인은 false입니다.
- 확인·수정 후 기존 POST /listings에 source_extraction_id와 IMAGE_REVIEWED 확인 정보를 보냅니다. 그 다음 별도 분석 요청을 합니다. 자동 등록·분석은 없습니다.

## 프론트가 할 일
기존 세션 토큰을 사용합니다. 판독 결과를 미리 보여준 뒤 사용자가 선택한 카드 번호로 저장 요청을 보내고, 응답 id로 listing-draft를 읽습니다. 주소·법정동 코드·주택 유형·면적이 전용인지·관리비 5항목 체크는 확인해야 하며 백엔드는 만들지 않습니다. 관리비 총액이 있다는 이유만으로 포함 항목을 체크하지 않습니다. 현 경로는 사진 업로드 API가 아니라 이미 읽은 값의 일치 확인 API입니다. 실제 엔진 판독 실행과 화면 연결은 별도입니다.

## 오류
401/403: 세션 필요. 422: 금액·입력·카드 번호 오류 또는 전세(현재 월세 연결만 지원). 409: 합의되지 않은 카드. 503: 분석 합의 모듈 미설치. 엔진 2~5개, 엔진별 최대 300개, 빈 이름 금지. 초과 데이터를 임의로 자르지 않습니다.

## 제한
고객이 보내온 engine_reads의 이름·값만으로 실제로 두 엔진이 실행됐다고 보증하지 않습니다. 결과는 확인용 초안입니다. 둘이 같은 값을 읽어도 정확도 보장은 아닙니다. 단독/불일치 값은 저장 경로에서 자동 채우지 않습니다. 실제 외부 OCR·비전 API 호출 시험을 완료했다고 보고하지 않습니다.

## 집 서버
아직 적용하지 않았습니다. 새 팀 브랜치를 main에 합칠지는 별도 검토가 필요합니다. 개인 저장소에는 필요한 분석 원본과 백엔드를 함께 반영하므로 집에서 pull·기존 시작 방법으로 적용한 뒤 실제 요청을 확인해야 합니다. DB 스키마 변경은 없고 기존 extraction 저장·소유자 접근 제어를 사용합니다.
