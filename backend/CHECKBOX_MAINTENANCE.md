# 관리비 입력·결과 — 고객 결정 반영 (2026-10-21)

## 확정한 화면 방식

고객은 전기·수도·가스·인터넷·기타 중 관리비에 포함된 항목을 체크하고, **체크한 항목이 포함된 관리비 총액 한 칸**만 입력합니다. 항목별 금액을 요구하지 않습니다.
결과는 ①체크한 항목별 분석 참고 비용과 합계 ②체크하지 않은 항목별 분석 참고 비용과 합계를 나눠 보여줍니다. 고객 입력 총액은 첫 묶음에 함께 표시합니다. 미체크가 별도 청구 확정이라는 뜻은 아닙니다.

## 프론트 연결

POST /listings의 options 예시(총액은 만원):

```json
{
  "maintenance_input_mode": "CHECKBOX_TOTAL_V1",
  "maintenance_10k_krw": 7,
  "electricity_in_maintenance": "UNKNOWN",
  "water_in_maintenance": "INCLUDED",
  "gas_in_maintenance": "UNKNOWN",
  "internet_status": "INCLUDED",
  "other_in_maintenance": "INCLUDED"
}
```

5개 상태를 모두 보냅니다. 체크 INCLUDED / 미체크 UNKNOWN. 이 입력 방식은 항목별 금액과 별도 CLEANING/COMMON 선택을 받지 않습니다. 총액 미기재는 null, 명시된 무료만 0입니다. 아무것도 체크하지 않아도 5개 상태는 보내며 총액에서 항목을 역산하지 않습니다. 확정 전 입력·수정은 사용자 재확인을 받아 등록합니다. 기존 mode 없는 과거 상세입력은 호환·보존합니다.

GET /listings/{id}/report의 새 `maintenance_reference_groups`:

- `advertised_selected_total_10k_krw`: 고객이 입력한 관리비 총액
- `selected.items`: 체크한 항목
- `unselected.items`: 체크하지 않은 항목. 포함 여부 미확인임을 표시
- 각 항목 `reference_state`, `reference_low_krw`, `reference_high_krw`, `source`
- 각 묶음 `reference_low_total_krw`, `reference_high_total_krw`, `missing_items`
- 현 실행은 분석 미연결이므로 `REFERENCE_NOT_CONNECTED`, 참고 금액·합계 null. 프론트는 ‘자료 없음’ 표시
- 기존 방식 자료는 `LEGACY_INPUT_REVIEW_REQUIRED`: 확인 없이 체크 여부를 확정하지 않기

참고 금액은 **원**, 고객 입력 총액은 기존 계약대로 **만원**입니다. 관리비 추정 기능 보류 상태에서도 고객 선택과 미연결 상태는 조회할 수 있으나 실제 추정 계산은 실행하지 않습니다. 기존 advertised_costs·utility_estimate 응답은 보존합니다.
