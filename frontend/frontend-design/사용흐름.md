## 1. 주제와 현재 범위

**매물 조건과 공공 실거래 데이터를 활용한 월세 비교 서비스.** 도시 생활 데이터로 시세 탐색 부담과 주거 정보의 비대칭을 줄인다(Smart City & Life Data).

유사한 신규 월세 실거래의 중앙값·중간 50% 가격대·차액·차이율·근거를 제공한다. 동네 전체의 단순 평균이나 사기 판정으로 표현하지 않는다.

| 기능 | 백엔드 전달 자료의 상태 | 화면 원칙 |
|---|---|---|
| 직접 입력·저장·월세 분석·보고서 | 백엔드 검증 완료로 전달, 프론트 PC 통합 남음 | 우선 연결 |
| 주소 검색·캡처 추출 | 코드·모의 검증 있음, 실제 외부 키 호출 미검증 | 목표 흐름 유지, 준비 상태와 직접 입력 대안 제공 |
| 건축물대장으로 유형·준공연도 자동 채움 | 서비스 API·응답 필드 미명시 | D02 합의 전 자동 확보 약속 금지 |
| 같은 건물 우선·개별 거래 목록·새 신뢰도 % | 현재 연결된 v1.1에서 미제공 | 현재 결과에 표시하지 않음, D04 논의 |
| 관리비·공과금·총 주거비 | 관련 API·화면 보류 | 평균 대입·합계·추천 비용 표시 금지 |
| 내 매물 목록·삭제 | API 제공, 프론트 연결 요청 | D05 범위 합의 후 포함 |

## 2. 전체 흐름

현재 우선 연결: **팀 테스트 접속 → 세션 발급·지원 범위 확인 → 직접 입력 → 사용자 확인 → 매물 저장 → 분석 요청 → 보고서 조회 → 결과.**

유지할 목표 입력 흐름:
1. 캡처 파일 첨부 또는 주소로 직접 찾기.
2. 캡처 텍스트 추출 또는 주소 확인. 건물 정보 조회는 별도 합의·구현 후 연결.
3. 부족한 필수값 수기 입력·자동 입력값 확인.
4. 위 경로와 동일하게 저장 → 분석 → 보고서 조회.

| 화면 ID | 화면 | 주요 행동 |
|---|---|---|
| UI-00 | 팀 테스트 접속 | 실제 연동 시 키 입력·세션 생성. 일반 사용자 로그인과 구분 |
| UI-01 | 입력 방식 선택 | 직접 입력 기본, 주소·캡처는 검증 전 상태 표시 |
| UI-02 | 정보 추출·조회 | 원문·추출값·주소 후보 확인, 미제공 건물 정보는 빈칸 |
| UI-03 | 보완·확인 | 검증·사용자 확인·저장/분석/조회 진행과 오류 안내 |
| UI-04 | 결과 | rent.result의 상태·가격·근거, 조건 수정 |
| UI-05 | 목록·삭제 | 포함 여부 D05 논의. 개별 삭제와 세션 전체 삭제 구분 |

## 3. 직접 입력·주소 경로

직접 입력은 자치구·법정동·유형·면적과 기준·보증금·월세를 입력한다. 내부 지역 코드를 사용자에게 외워서 쓰게 하지 않는다. 주소 설명·준공연도·층은 아는 범위에서 보완한다.

주소 검색 연결 후에는 `GET /addresses/search?q=검색어` → 후보 선택 → 법정동 코드 확인 → 정보 보완으로 진행한다. 프론트는 백엔드 검색 API를 사용한다. 건물명 검색 범위와 후보 응답 형식은 확인이 필요하다.

현재 분석 계약은 자치구 코드와 법정동 코드 또는 법정동명을 요구한다. 정확한 지번·건물명은 현재 분석의 필수값이 아니다. 서비스에서도 동네 수준 비교를 허용할지는 D03에서 결정한다. HTML은 이를 허용하는 시안이며, 실서버의 법정동명 입력 수용 여부도 통합 확인 대상이다.

주소만으로 현재 광고의 보증금·월세·호실 면적을 알 수 없다. 과거 거래 가격이나 건물 전체 면적을 대입하지 않는다. 유형·준공연도 자동 조회는 D02 합의 전까지 수기 또는 미확인으로 처리한다.

## 4. 캡처 경로

1. 이미지 한 장 선택. 이미지 8MB·전체 요청 9MB를 안내한다. 정확한 바이트 기준과 허용 MIME 목록은 서버 명세로 확정한다. JPG·PNG·WebP는 시안의 형식 제안이다.
2. `POST /extractions`에 multipart 필드 `file`로 업로드. Content-Type의 boundary는 브라우저가 생성한다.
3. 추출 ID로 `GET /extractions/{id}/listing-draft` 조회.
4. 원문 근거·추출값·확인 필요 여부 표시. 없는 값은 null 또는 UNKNOWN.
5. 주소 후보 선택 또는 직접 입력으로 보완. 건물명만으로 지번 확정 금지.
6. 사용자 확인 후 `source_extraction_id` 및 `confirmation.input_source=IMAGE_REVIEWED`와 함께 매물 저장.
7. 이후 분석·보고서 조회는 직접 입력과 동일.

외부 호출 검증 전에는 준비 상태를 안내한다. 여러 매물·추출 실패는 재첨부 또는 직접 입력. 이미지 보관·삭제·AI 전송 안내는 D07에서 확정한다.

## 5. 입력 필드와 확인 규칙

| 항목 | 필드 | 기준 |
|---|---|---|
| 규격 | schema_version | 최상위 문자열 "1.1" |
| 자치구 | listing.district_code | 5자리 문자열, /capabilities 지원 범위 |
| 법정동 | listing.legal_dong_code 또는 listing.dong | 법정동 10자리 코드 또는 이름. 행정동 코드와 구분 |
| 주소·호수 | listing.address_text / unit_ho | 입력 예시에 존재. 불필요한 상세 호수 강제하지 않음 |
| 유형 | listing.building_type | APARTMENT / MULTI_UNIT / OFFICETEL / DETACHED_MULTI. 원룸·빌라만으로 확정 금지 |
| 면적 | listing.area_m2 | 5~200㎡, 호실 면적 |
| 기준 | listing.area_basis | EXCLUSIVE / SUPPLY / CONTRACT / RENTAL_REPORTED / UNKNOWN |
| 보증금 | listing.deposit_10k_krw | 만원, 0 이상. 0과 빈값 구분 |
| 월세 | listing.rent_10k_krw | 만원, 1~500. 전세 제외 |
| 준공연도 | listing.built_year | 선택, 미확인 null. 기존 분석 코드 유효 범위 1950~현재 연도+1 |
| 호실 층 | listing.floor | 선택 정수, 0·빈값은 null, 음수는 지하 |
| 지상·지하 | listing.floor_type | GROUND / BASEMENT / UNKNOWN |
| 층 출처 | listing.floor_source | USER_CONFIRMED / IMAGE_EXTRACTED / UNKNOWN |
| 확인 | confirmation.user_confirmed | true 확인 후 분석. 주요 값 수정 시 해제 |
| 확인 필드 | confirmation.confirmed_fields | 실제 확인한 필드 목록, 층 확인 UI와 연결 |
| 입력 경로 | confirmation.input_source | ADDRESS_MANUAL / IMAGE_REVIEWED |
| 캡처 연결 | source_extraction_id | 실제 추출 ID. 직접 입력은 생략 가능 |
| 옵션 | options | 현재 핵심 흐름은 {}. 관리비 화면 보류 |

**SUPPLY는 가격 판정 보류. UNKNOWN은 현재 v1.1에서 전용면적으로 가정하고 경고한다.** 프론트가 미확인을 무조건 REFERENCE_ONLY로 바꾸지 않는다. 단독·다가구는 계약면적·층·신뢰도 등 별도 정책도 적용되므로 최종 응답을 따른다. 미확인을 반드시 보류하려면 D06에서 분석 정책·코드·계약을 함께 바꾼다.

층 숫자와 지상·지하가 모순되면 재확인한다. AI 추출 층은 사용자 확인 전 판정 근거가 아니다. 층을 확인했을 때만 USER_CONFIRMED와 확인 필드를 전달한다. 미확인 층은 허용하며 참고 처리될 수 있다.

자동 입력값은 원문·출처와 함께 보여주고 수정 가능하게 한다. 사용자 수정 뒤에는 직접 입력으로 표시한다. 건물 조회 응답의 출처 메타데이터는 합의 전이다.

## 6. 서비스 API 연결

| 순서 | 요청 | 처리 |
|---|---|---|
| 1 | POST /sessions | X-Team-Key로 발급, 응답 token 보관 |
| 2 | GET /health, GET /capabilities | data_status=READY 및 실제 지원 지역·기능 확인 |
| 3 | POST /listings | JSON 저장, HTTP 201의 id를 listingId로 보관 |
| 4 | POST /listings/{listingId}/analyses | HTTP 201이어도 result.status를 별도로 확인 |
| 5 | GET /listings/{listingId}/report | property.input과 rent.result 사용 |
| 선택 | GET /listings?limit=20&offset=0 | items·has_more로 페이지 처리 |
| 선택 | DELETE /listings/{listingId} | 204, 매물과 연결 분석 삭제 |
| 선택 | DELETE /sessions/current | 204, 세션 자료 전체 삭제. 창 종료 때 자동 호출 금지 |

모든 실제 요청에 X-Team-Key, 세션 생성 이후 Authorization: Bearer <token>을 함께 쓴다. JSON 본문은 Content-Type: application/json. 키는 테스트 시작 시 입력받아 메모리에서만 사용하며 소스·배포 파일·로그에 넣지 않는다. 세션 토큰을 잃었을 때 계정으로 복구하는 기능은 아직 없다.

백엔드는 미확인 입력도 저장할 수 있지만 분석에는 사용자 확인이 필요하다. 현재 UI는 확인 후 저장하는 흐름을 선택한다.

현재 CORS 허용 주소: http://localhost:5173, http://localhost:3000. 다른 실행 주소는 백엔드에 등록 요청한다. file:// HTML은 화면 검토용이다. 임시 서버 주소는 재시작 시 바뀔 수 있으므로 최신 전달 주소를 사용한다.

조건 수정 후 기존 매물 갱신인지 새 매물 생성인지, previous_listing_id의 사용법은 D08에서 합의한다. PATCH 경로를 임의로 만들지 않는다. 저장 성공 후 분석·조회 실패 시 기존 listingId와 입력을 유지하고 무조건 새 매물을 생성하지 않는다. 중복 분석·재시도 정책도 D08 대상이다.

## 7. 결과 표시

| 내용 | 보고서 경로·규칙 |
|---|---|
| 입력 요약 | property.input |
| 분석 상태·라벨 | rent.result.status / price_label |
| 중앙값·중간 50% | rent.result.prices_10k_krw의 median / q25 / q75 |
| 차액 | rent.result.rent_difference_10k_krw, 만원 |
| 차이율 | rent.result.rent_difference_pct는 비율. -0.556 → -55.6% |
| 근거 | sample_count / reference / comparison의 실제 제공값 |
| 신뢰도 | confidence_grade 및 설명. 새 신뢰도 %·사기 확률·정확도 보장 금지 |
| 경고·보류 | messages / warning_texts / hold_reasons / reason_codes / errors / input_issues |
| 출처·기준일 | data_source / data_as_of. rent.analyzed_at과 구분 |
| 개별 거래 | rent.comparable_transactions=null, NOT_PROVIDED_BY_ANALYSIS. 가짜 목록 금지 |

현재는 같은 법정동 → 조건 완화 → 같은 자치구로 확대한다. 실제 reference.conditions.scope를 표시한다. 정확한 주소를 받았다는 이유로 ‘같은 건물 비교’라고 쓰지 않는다. analysis_internal/engine_v2.py는 현재 서비스와 별개다.

| 상태 | 화면 |
|---|---|
| COMPARED | 반환된 라벨·가격·차이·근거 |
| REFERENCE_ONLY | 제공된 참고 범위와 보류 이유, 판정 라벨 생성 금지 |
| INSUFFICIENT_DATA | 자료 부족·조건 수정, 임의 평균이나 0원으로 대체 금지 |
| INPUT_REVIEW_REQUIRED | 수정할 항목·이유와 입력 화면 연결 |
| OUT_OF_SCOPE | /capabilities 기준 지원 범위 안내 |

분석 결과나 숫자가 없으면 미제공으로 표시한다. maintenance / utility_costs / monthly_cost / utility_estimate의 ON_HOLD 상태로 총비용을 만들지 않는다.

## 8. 오류·진행 상태

| 상황 | 동작 |
|---|---|
| 401 | 키·토큰 확인. 새 세션 발급이 기존 자료 복구를 의미하지 않음 |
| 404 | 현재 세션에서 조회할 수 없는 자료 안내 |
| 413 | 이미지 8MB·전체 요청 9MB 안내 후 재첨부 |
| 422 | 잘못된 필드 안내, 입력 유지 |
| 503 | 실거래·외부 API 준비 상태 또는 기능 보류를 응답대로 안내 |
| 네트워크·시간 초과 | 실패 단계·재시도 표시, 받은 ID와 입력 유지 |
| 주소 없음·다수 후보 | 재검색·후보 선택. 동네 비교 대안은 D03 |
| 건물 조회 실패 | 기능 구현 후 적용. 주소 유지·수기 보완 |

저장 중 → 분석 요청 중 → 보고서 조회 중을 구분하고 중복 제출을 막는다. HTTP 오류, 분석 상태, ON_HOLD·NOT_PROVIDED_BY_ANALYSIS 같은 기능 상태는 구분한다.

| 팀 공동 | 아래 범위·정책 결정 후 문서·화면·API 동기화 |

## 11. HTML·CSV 사용법과 구현 범위

HTML은 설치 없이 브라우저로 여는 **오프라인 화면 설계 시안**이다. 실제 API 호출·키 입력·이미지 전송·DB 저장을 하지 않는다.

- 직접 입력 → 백엔드 예시 값 불러오기 → 최종 확인 → 저장·분석·조회 흐름 시연 → 결과.
- 백엔드 제공 가상 예시: 월세 80만원, 중앙값 180만원, Q25~Q75 156~200만원, 42건, 차액 -100만원, 차이율 -55.6%.
- 다른 입력에는 고정 가격 결과를 재사용하지 않는다. 실제 분석 연결 전이라고 안내한다.
- 상태별 미리보기는 UI 검토용 가상 상태이며 해당 입력의 실제 분석 결과가 아니다.
- 캡처·주소는 검증 전 경로의 시연이다. 파일의 형식·크기만 검사하고 내용을 읽거나 전송하지 않는다. 시안은 보수적으로 8,000,000바이트까지 허용하며 서버 기준 확정 후 맞춘다.
- 목록·삭제 후보 시안은 페이지 메모리만 사용하며 새로고침 시 사라진다. 실제 DB·세션 삭제가 아니다. 범위 D05 미확정.
- 팀 연동 메모에 API 순서·요청 JSON 미리보기를 둔다. 일반 사용자 흐름에서 내부 코드를 요구하지 않는다.
- 요구사항 정의서는 위 Google 스프레드시트에서 관리한다. 로컬 CSV는 사용하지 않는다. 내 매물 목록·삭제는 팀 합의 전이므로 현재 요구사항에서 제외했으며, 아래 HTML의 해당 화면은 이전 검토 후보 시안이다.
