# 월세 비교 서비스 사용 흐름

- 버전: v0.5 / 갱신일: 2026-10-20
- 대상: 프론트엔드·백엔드·데이터 분석 담당 및 프로젝트 검토자
- [로컬 HTML 시안](월세비교_화면흐름.html)
- [공유 시안](https://munhwadream-rent-preview.zxaq3166.chatgpt.site/)
- [요구사항정의서 — 초안](https://docs.google.com/spreadsheets/d/1D8E9QjkNiDwWqL32SAmZechF-bOX3Pjsi92FhLItBRE/edit)

이 문서는 10월 20일 합의한 화면 흐름과 현재 HTML의 동작을 설명한다. **HTML은 실제 API·분석 코드·DB에 연결되지 않은 가상 시안이다.** 화면에 기능이 있다고 백엔드 연동이 완료된 것은 아니다.

## 1. 서비스 목적과 범위

사용자가 관심 있는 매물의 조건을 입력하면, 같은 법정동 안의 유사한 월세 실거래와 비교해 기준 월세·가격 범위·차이·근거를 제공한다. 도시 생활 데이터로 시세 탐색 부담과 주거 정보의 비대칭을 줄이는 서비스다.

- 현재 연동 기준은 같은 법정동 우선 비교이며, 같은 건물 우선 비교가 아니다.
- 시군구·법정동이 확인되면 정확한 건물 주소 없이도 월세 분석을 요청할 수 있는 흐름으로 설계한다.
- 건물 주소는 건축연도 등 조회 가능한 정보를 자동 보완하기 위한 선택 정보다.
- 월 관리비는 금액 하나만 입력받는다. 결과에는 월세 비교와 별도로 예상 공과금·인터넷 비용 및 참고 합계를 표시한다.
- 가격 차이는 사기 여부나 매물의 안전성을 뜻하지 않는다.
- 내 매물 목록·삭제·로그인·팀 접속 화면은 현재 시안 범위에서 제외한다.

## 2. 화면별 역할

| 화면 | 역할 | 다음 단계 |
| --- | --- | --- |
| 1. 입력 방식 | 캡처 첨부 / 주소 검색 / 직접 입력 선택 | 캡처·주소는 정보 가져오기, 직접 입력은 입력·확인 |
| 2. 정보 가져오기 | 추출·조회 결과와 출처를 읽기 전용으로 확인 | 정보 확인 후 입력·확인 |
| 3. 입력·확인 | 지역과 매물 조건 보완·수정, 불일치 확인, 최종 확인 | 월세 비교하기 |
| 4. 결과 | 월세 비교, 근거, 비용 추정 내역과 합계 확인 | 조건 수정 또는 다른 매물 비교 |

2번 화면에서는 값을 수정하지 않는다. 후보 선택·수기 보완·최종 확인은 3번 화면에서 진행한다.

## 3. 입력 경로

### 캡처로 입력

1. 매물 주소·면적·보증금·월세 등이 보이는 이미지를 첨부한다.
2. 정보를 추출하고, 추출 주소로 지역과 건물을 확인한다.
3. 2번 화면에 확인된 값·출처·미확인 항목을 표시한다.
4. 3번 화면에서 부족한 값과 불일치 정보를 보완하고 최종 확인한다.

| 주소 확인 수준 | 설계한 처리 |
| --- | --- |
| 정확한 건물 주소 확인 | 표준 주소 반영 → 건물 조회 → 빈 항목 보완 |
| 시군구·법정동까지 확인 | 비교 지역 반영. 건물 선택 없이 분석 가능 |
| 지역 누락·불명확 | 3번 화면에서 시군구·법정동 선택 요청 |
| 건물 후보 여러 개 | 3번 화면에서 후보 선택 제공. 지역이 확인됐다면 건물 선택은 필수가 아님 |

사진에서 추출하거나 사용자가 입력한 값을 건물 조회값으로 임의 덮어쓰지 않는다. 값이 다르면 두 값과 출처를 보여주고 확인받는다. 건물 전체 면적이나 과거 거래금액을 현재 호실의 면적·보증금·월세로 채우지 않는다.

현재 시안은 전체 흐름 검토를 위해 정확한 주소가 확인되는 가상 캡처 예시로 고정했다. 캡처 주소 예외상황 선택 메뉴는 제거했으며, 위 예외 흐름은 실제 연결 시 검증할 대상이다.

### 주소로 입력

주소를 검색·선택하고 조회 가능한 건물 정보를 가져온다. 조회 결과는 2번 화면에서 확인하고, 해당 호실의 면적·보증금·월세 등은 3번 화면에서 보완한다. 주소만으로 현재 광고의 임대 조건을 확정하지 않는다.

### 직접 입력

바로 3번 화면으로 이동한다. 시군구·법정동과 매물 조건을 입력한다. 건물 정보를 자동으로 가져오고 싶은 경우에만 선택용 건물 주소 검색을 사용한다.

## 4. 입력·확인 화면

| 구역 | 항목 | 입력 원칙 |
| --- | --- | --- |
| 비교 지역 | 시군구·법정동 | 필수. 행정동이 아닌 법정동을 사용 |
| 건물 주소 | 정확한 주소 검색 | 선택. 건물 조회용 |
| 매물 조건 | 주택 유형, 면적(㎡), 면적 기준 | 필수. 면적 기준은 미확인 선택 가능 |
| 매물 조건 | 보증금·월세 | 필수, 각각 만원 단위 |
| 매물 조건 | 월 관리비 | 입력칸 하나, 만원 단위. 모르면 비워둠 |
| 추가 정보 | 건축연도 | 선택. 미입력 시 건축연도 조건 없이 비교한다는 안내 |
| 추가 정보 | 해당 호실 층·지상/지하 | 선택. 미확인 허용 |
| 최종 확인 | 입력 정보 확인 | 확인 후 비교 요청. 값 변경 시 확인 해제 |

- 지역 선택은 현재 시안에서 서울 관악구 봉천동·신림동만 예시로 제공한다. 실서비스는 지원 지역 목록으로 구성한다.
- 관리비의 포함 항목·항목별 금액 입력칸은 제공하지 않는다. 빈값과 실제 0원을 구분한다.
- 건물 주소 변경 시 이전 조회값은 갱신하거나 비운다. 사진·직접 입력값은 유지하며 다른 건물로 바뀐 경우 재확인한다.
- 비교 지역 변경 시 이전 건물 주소·조회값·후보를 해제한다. 사진·직접 입력값은 유지하고 필요한 재확인을 요청한다.
- 필수값 누락·잘못된 숫자·층과 지상/지하의 모순·미해결 불일치·최종 확인 누락은 안내 후 보완한다.
- 재분석 전에는 이전 결과를 수정된 입력의 결과로 표시하지 않는다.

## 5. 실제 월세 분석의 기본 원리

현재 v1.1 기준이며, HTML의 고정 예시 계산과 구분한다.

1. 시군구와 법정동으로 비교 지역을 정한다.
2. 주택 유형·면적·보증금으로 유사 실거래를 선별한다. 건축연도·지상/지하 여부·계약 시점은 확인 가능한 정보와 유형별 기준에 따라 반영한다.
3. 거래가 부족하면 같은 법정동 안에서 조건을 완화하고, 이후 같은 자치구 전체로 확대한다.
4. 선별한 거래의 월세 중앙값과 입력 월세를 비교한다.

건축연도 허용 범위는 1차 ±5년, 2차 ±10년이며 3차에서는 제한을 해제한다. 건축연도 미입력은 해당 조건을 적용하지 않고 신뢰도에 반영한다. 비교 거래의 연도가 누락된 경우도 코드상 후보에 포함될 수 있다.

- 차액 = 입력 월세 − 기준 월세 중앙값
- 차이율(%) = 차액 ÷ 중앙값 × 100
- 가격 범위 = 비교 거래의 중간 50% 구간(Q25~Q75)
- 같은 자치구 전체로 확대한 결과는 참고용이며 높고 낮음을 판정하지 않는다.

분석의 최종 상태·라벨은 응답값을 따른다. 공급면적·미확인 면적 기준·단독다가구 층 등 유형별 정책은 분석 계약을 따른다.

## 6. 결과 화면

| 영역 | 표시 내용 |
| --- | --- |
| 결과 상태 | 비교 완료 / 참고용 / 자료 부족 / 입력 확인 필요 / 지원 범위 밖 |
| 대상 요약 | 비교 지역, 확인된 건물 주소가 있으면 주소, 주택 유형·면적·금액 등 |
| 월세 비교 | 중앙값, 중간 50% 가격 범위, 차액·차이율, 허용되는 경우 가격 위치 |
| 비교 근거 | 거래 수, 지역, 계약일 범위, 적용 조건과 확대 여부 |
| 신뢰도 | 제공된 등급·사유. 사기 확률이나 정확도 보장으로 표현하지 않음 |
| 비용 참고 | 아래의 입력 금액 합계와 추정 금액 합계 |
| 출처·한계 | 자료 출처·기준 시점·적용 지역·미반영 조건 |
| 후속 행동 | 조건 수정 / 다른 매물 비교 |

참고용 결과는 가격 판정을 숨긴다. 자료가 없으면 임의의 가격이나 0원을 표시하지 않는다. 개별 비교 거래 목록은 현재 분석에서 제공되지 않아 화면에 만들지 않는다.

### 관리비와 예상 공과금·인터넷 비용

| 구분 | 계산과 표시 |
| --- | --- |
| 입력 매물 | 입력 월세 + 입력 월 관리비 |
| 비교 기준 | 기준 월세 + 예상 수도·전기·가스·인터넷 합계 |
| 추정 내역 | 수도 / 전기 / 가스 / 인터넷의 월 적용 금액을 각각 표시하고 합계 표시 |

입력 관리비에 추정 공과금을 다시 더하지 않는다. 관리비 미입력 시 입력 매물 합계를 확정하지 않으며, 추정 항목 중 자료가 빠지면 전체 추정 합계를 만들지 않는다.

포함 항목을 입력받지 않으므로 두 합계가 동일한 비용 범위를 의미하지 않는다. 수도·전기·가스·인터넷 합계는 청소·공용관리 등까지 포함한 관리비 전체 평균이 아니다. 합계 차이로 비싸다·저렴하다를 판정하지 않으며 월세 판정과 분리한다.

이 비용 화면은 제품 설계 및 가상 시안에 반영한 내용이다. **최신 백엔드는 광고 관리비 입력·저장·표시는 지원하지만, 평균 비용 추정·비교는 아직 ON_HOLD이다.** 실제 연동 시 보류 응답을 실제 추정값으로 바꿔 표시해서는 안 된다.

## 7. 시안 확인 방법

### 1번 화면: 입력 방식

- 맨 위 네이비 **가상 캡처 넣기**: 가상 첨부 표시를 채운다. 이어서 **가상 추출 결과 확인**을 눌러 2번으로 이동한다.
- 맨 위 네이비 **가상 주소 넣기**: 가상 주소를 채운다. 이어서 **건물 정보 가져오기**를 눌러 2번으로 이동한다.
- 두 버튼은 값을 채울 뿐 다음 화면으로 자동 이동하지 않는다.

### 2번 화면: 정보 가져오기

가져온 값만 확인한다. 별도의 예시 값 입력 버튼은 없다. **입력·확인으로** 버튼으로 3번에 이동한다.

### 3번 화면: 입력·확인

맨 위 네이비 **예시 값 채우기**를 누르면 매물 조건과 관리비가 채워진다. 현재 화면에 머물며, 사용자가 최종 확인에 체크하고 **월세 비교하기**를 눌러야 결과로 이동한다.

직접 입력한 다른 조건도 필수 입력·확인 조건을 충족하면 가상 결과를 볼 수 있다. 정해진 예시와 다르다는 이유로 ‘분석 미연결’ 화면을 표시하지 않는다.

### 4번 화면: 가상 결과

- 월세 중앙값 180만원, 범위 156~200만원, 거래 42건은 입력 조건과 무관한 고정 예시다.
- 차액·차이율은 입력 월세와 가상 기준 180만원으로 계산한다.
- 비용 예시는 수도 1만원·전기 3만원·가스 4만원·인터넷 3만원, 합계 11만원이다. 실제 동네 평균이 아니다.
- 예시 값 채우기의 월세 80만원·관리비 8만원이면 입력 합계는 88만원, 가상 기준 180만원 + 11만원은 191만원이다.
- 결과 상태 미리보기는 화면 검토용으로 남아 있다. 자료 부족 등 가격 미제공 상태에서는 기준 가격과 추정 합계도 미제공 처리한다.

파일은 PNG·JPEG·WebP, 8MiB 이하를 시안에서 허용한다. 실제 이미지 내용은 읽거나 전송하지 않으며, 추출 결과는 가상 데이터다. 선택한 주소·입력값도 서버에 저장하지 않는다. 새로고침하면 초기화된다.

## 8. 실제 연결 시 확인할 사항

| 항목 | 남은 작업 |
| --- | --- |
| 입력 매핑 | HTML 내부 필드명을 분석 계약의 listing/options/confirmation으로 변환. 유형·면적 기준 enum도 계약과 맞춤 |
| 지역 목록 | 백엔드가 제공하는 지원 시군구·법정동 목록 연결 |
| 주소·캡처 | 외부 API 준비 상태 확인, 실제 조회·추출 응답과 사용자 확인 연결 |
| 건물 자동 보완 | 조회 가능한 필드와 출처 확정. 사용승인일 연도를 분석용 건축연도로 사용할지 협의 |
| 관리비 금액 | options.maintenance_10k_krw로 전달, 미입력 null과 0 구분 |
| 광고 관리비 응답 | report.advertised_costs 사용. 이번 UI에서 받지 않는 항목은 포함 여부나 금액을 추측하지 않음 |
| 비용 추정 | 별도 자료·산정 기준·응답 규격 합의 필요. 항목별 금액·단위·출처·지역·기준 시점·자료 상태 포함 |
| 실제 결과 | 가상 가격·거래 수·비용을 제거하고 반환값만 표시. ON_HOLD/null은 그대로 안내 |
| 저장·분석·보고서 | 최신 백엔드 연결 모듈을 이용하고 실제 화면에서 검증. 키는 소스·문서에 기록하지 않음 |

백엔드에는 관리비 포함 항목·명시 금액 등을 저장하는 확장 규격도 있지만, **이번 UI는 사용자 요청에 따라 월 관리비 금액 하나만 받는다.** 추정 비용 기능을 서버가 구현한 것으로 문서화하지 않는다.
