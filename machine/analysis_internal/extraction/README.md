# extraction — 광고 문구 · 이미지 구조화

광고의 금액 · 포함/별도 · 정액/실비 표기를 규칙으로 읽어 구조화합니다. 이미지는 OCR(EasyOCR 등)로 글자를 읽은 뒤 이 규칙 파서를 거치며, **읽은 값은 사용자가 확인한 뒤에만** 계산에 씁니다.

| 파일 | 역할 |
|---|---|
| `parse_detail.py` | 상세보기(다방 · 직방) 관리비 영역 → 총액 · 포함 항목 · 별도 실비 · 부과 방식. 합계가 맞지 않으면 보류 |
| `ad_cards.py` | 목록 카드(다방 · 직방 형식별) → 월세 · 보증금 · 면적 · 관리비 |
| `parse_ad_text.py` | 광고 문구 붙여넣기 → 필드 (시험판 화면에서 사용) |
| `consensus.py`, `test_consensus.py` | 여러 엔진이 읽은 목록 카드 값 중 **둘 이상이 같게 읽은 값만** 자동 입력 후보로 올림(`extracted`). 한 엔진만 읽었으면 `on_hold`, 같은 카드에 금액이 엇갈리면 `needs_review`(후보만 표시, 값은 비움). 값을 고치거나 추측하지 않고 `AREA_OVER_100_M2` 같은 경고 사유만 붙임. 출력은 3번 머신(`listing_extractor`) 형식 |
| `test_parse_detail.py`, `test_parser.py` | 파서 회귀 시험 (개발용 표본 기준) |

지원 범위와 한계는 [`../../docs/maintenance_validation.md`](../../docs/maintenance_validation.md). 실제 광고 캡처는 저장소에 올리지 않습니다.

## 합의(consensus) 평가 — 개발에 쓰지 않은 목록 카드 46개 (로컬 캡처, 저장소에는 없음)

| 방식 | 읽은 값 중 정답 | 틀린 값 | 못 읽음/보류 |
|---|---|---|---|
| Qwen2-VL 단독 | 33 | 22건(정답 카드에 연결 안 되는 것 포함) | 13 |
| EasyOCR 단독 | 30 | 3건 | 16 |
| PaddleOCR 단독 | 28 | 0건 | 18 |
| **둘 이상 일치(`consensus.py`)** | **32** | **1건** (면적 20.1㎡를 201㎡로 두 엔진이 같이 오독, `AREA_OVER_100_M2` 경고가 붙음) | 14 (on_hold 12 + needs_review 2) |

- 값만 보는 범위 검사는 Qwen 틀린 읽기 22건 중 7건만 잡았다(그럴듯한 값이 다른 카드와 섞임). 그래서 범위 검사는 오류 탐지 경고로만 쓰고, 자동 입력 여부는 엔진 합의로 정한다.
- 46카드는 다방 목록 화면이고 표본이 작아 일반화 정확도가 아니다. 직방 · 상세 페이지 · 사진 속 글자 · 백엔드가 쓰는 OpenAI 비전 경로는 아직 평가하지 않았다.
- 어떤 상태든 사용자가 확인하기 전에는 월세 비교 · 관리비 추정에 넘기지 않는다(`user_confirmed` 는 이 모듈이 켜지 않는다).

백엔드 연결: `POST /extraction/card-consensus` (`backend/app/card_consensus.py`, 저장하지 않는 순수 함수). 이미지 추출 서비스가 엔진별 읽기를 `engine_reads`(엔진 2~5개)로 보내면 합의된 값만 `extracted`로 돌려준다. 엔진 실행(OCR 호출)은 아직 백엔드에 없다.

## 두 번째 독립 평가 — 새로 캡처한 다방 목록 13화면, 새 카드 74개 (2026-10-22, 로컬 캡처, 서울·경기 지도 범위)

| 방식 | 완전 정답 | 읽은 값 중 틀림 | 보류 |
|---|---|---|---|
| EasyOCR | 45/74 (61%) | 8 | 29 |
| PaddleOCR | 43/74 (58%) | 8 | 31 |
| Qwen2-VL | 53/74 (72%) | 10 | 21 |
| **합의(둘 이상 일치)** | 46/74 (62%) | **7** (경고가 붙은 것은 1건뿐) | 28 |

- **첫 번째 평가(46카드)의 "합의 틀린 값 1건"은 이 표본에서 재현되지 않았다.** 합의 값 53건 중 7건이 틀렸고 대부분 경고가 없다. 합의가 안전하다고 말할 수 없다.
- 원인(1건 직접 확인): 같은 건물의 매물이 **가로 두 칸**으로 나란히 보이는 화면에서, 왼쪽 카드의 면적·관리비가 오른쪽 카드의 월세와 한 줄로 묶였다. 세 엔진이 같은 줄 묶기·파서를 거치므로 **같은 실수를 같이 해서 일치**했다. 나머지 6건도 같은 건물 매물의 면적·관리비와 맞아 같은 원인으로 보이나 개별 확인은 하지 않았다.
- 결론: 엔진 합의는 엔진마다 다른 오독은 걸러도 **줄 묶기·카드 분리 같은 공통 오류는 못 거른다.** 다음 개선은 카드를 열(column)별로 먼저 나누는 것.
- 한계: 캡처와 DOM(정답)을 몇 초 간격으로 따로 읽어 화면이 바뀐 경우가 섞였을 수 있고, 13화면 중 3화면은 정답 카드가 없었다.

## 실행하기 — `read_cards.py` (이미지 → 확인용 초안)

```bash
pip install -r machine/analysis_internal/extraction/requirements-ocr.txt      # 선택 설치(백엔드·합의 모듈은 없어도 동작)
python machine/analysis_internal/extraction/read_cards.py 목록캡처.png --crop 80,170,480,3600 --out result.json
```

- EasyOCR와 PaddleOCR(PP-OCRv5 한국어)로 읽고, 카드를 **열(column)별로 먼저 나눈 뒤** 줄로 묶어 파서에 넣고, 두 엔진이 같게 읽은 값만 `extracted`로 채웁니다. 나머지는 `on_hold`/`needs_review`로 비워 둡니다. 모든 결과는 사용자 확인 전 초안(`user_confirmed=false`)입니다.
- 첫 실행에는 모델을 내려받고, CPU 기준 화면 1장(약 3,400px 높이)에 약 50초(모델 로딩 포함)가 걸렸습니다. 이 PC에서 다방 캡처 1장으로 끝까지 실행해 확인했습니다.
- 시험 범위: **다방 웹 목록 화면**(목록 열 폭 약 400px, `--crop 80,170,480,3600`)뿐입니다. 직방·다른 앱·휴대폰 캡처·사진 속 글자는 평가하지 않았습니다. 서비스 대상은 서울이며, 읽은 주소가 서울이 아닐 때 보류하는 안내는 아직 구현하지 않았습니다.
- 시험(OCR 패키지 없이 실행): `python test_read_cards.py`, `python test_consensus.py`

## 부분 입력 — 인식된 항목만 입력 (2026-10-23, 프론트 피드백 반영)
피드백: "이미지 분석은 입력 항목이 모두 있어야 넘어간다. 인식된 항목만 입력되게 해 달라(예: 사진에 주소만 있으면 주소만)."
원인(머신 쪽): ① 파서가 월세·면적·관리비가 모두 있는 카드만 인정(관리비 '없음'·미표기·잘린 카드는 통째로 버림), ② 카드 전체 값이 두 엔진에서 똑같아야 채움, ③ 목록이 아닌 화면(상세·사진)은 읽지 않고 주소 추출이 없었음.

바뀐 동작(`read_cards.py` 결과에 `cards`와 `image_fields`):
- **카드 항목별 입력**(`partial_fields.partial_cards`): 월세/전세 머리줄이 있는 카드에서 면적·관리비를 각각 찾고, 없으면 `None`. 값이 비정상이면 그 항목만 비운다(보정하지 않음). `관리비 없음`은 0.0(명시된 경우만; 전기·수도·가스가 없다는 뜻이 아님), 미표기는 절대 0으로 두지 않는다.
- **항목별 합의**(`consensus.py`): 카드 전체가 같으면 `extracted`. 같은 머리줄(종류·보증금·월세)에서 일부 항목만 엔진이 다르면 `partial` — 일치한 항목만 채우고(`agreed`), 다른 항목은 `conflict`, 한 엔진만 읽은 항목은 `read`(채우지 않음)로 비운다. 같은 머리줄 카드를 한 엔진이 여럿 읽으면 항목을 섞지 않고 `needs_review`.
- **이미지 단위 항목**(`image_fields`): 카드가 아닌 화면(상세·사진)도 주소 · 금액 · 면적 · 관리비를 라벨 기준으로 읽는다. 한 값으로 정해지지 않으면(서로 다른 값이 여럿) 읽지 않는다. 항목마다 `agreed`(두 엔진 일치, `autofill=true`) / `read`(한 엔진) / `conflict` / `missing`. 주소는 정규화된 **후보**(`resolution: candidate_needs_address_search`)이며 주소 검색으로 확인되기 전에는 확정이 아니다. 주소가 여러 개면 첫 번째를 고르지 않는다.
- 조각(타일) 경계에서 글을 나눠, 잘린 카드 뒤에 다음 조각의 다른 카드 글이 붙어 항목이 섞이지 않게 했다. 월세 카드인데 월세 금액이 없는(금액 표기가 깨진) 머리줄은 읽지 않는다.

회귀·항목별 정확도(이미 평가한 서울 다방 24화면·직방 17화면을 새 코드로 다시 읽음, 정답=같은 화면 DOM 텍스트를 같은 부분 파서로 읽은 값, 화면 단위 집계라 겹치는 화면의 카드는 중복 집계):
| | 머리줄 틀림 | 자동 입력된 면적·관리비 | 그중 틀림 | 항목이 비어도 합의된 카드 |
|---|---|---|---|---|
| 다방 | 0 | 857 | 0 | 0 |
| 직방 | 0 | 497 | 0 | 16 |

- 처음 코드에서는 직방에서 "관리비 없음→0원" 오입력 2건과 머리줄 1건이 틀렸다(조각 경계 글 섞임, 금액 표기가 깨진 머리줄). 위 두 가지로 고친 뒤 다시 읽어 위 표가 됐다. 같은 화면에서 고친 것이므로 새로 캡처한 화면으로 한 번 더 평가해야 한다.
- 한계: 주소 추출은 단위 시험(합성 텍스트)만 했고 실제 주소가 보이는 캡처로는 평가하지 않았다. 상세 화면·휴대폰 캡처·사진 속 글자의 항목별 정확도는 평가하지 않았다. 전체 화면을 넘길 때는 `--crop` 으로 목록 영역만 넘기는 것이 안전하다(다방 열 분리는 목록 열 폭 약 400px 기준).
- 시험: `python test_partial_fields.py`


## 평가 정정 — 정답을 '화면에 보이는 글자'로 다시 만들어 재평가 (2026-10-23)
**정정:** 위 평가들(다방 46·74·67카드, 직방 200카드)은 정답을 페이지 전체 텍스트(DOM)로 만들었다. 목록이 가상화되어 DOM에는 **화면 밖 카드까지** 들어 있어서, 읽을 수 없는 카드를 '못 읽음'으로 세어 자동 입력률이 낮게(보류 31~38%) 나왔다. 값의 정확도(틀림 0)에는 영향이 없다.

새 정답: 화면에 **완전히 보이는 글자 노드만**(글자 위치를 재서 뷰포트·목록 영역 안인 것) 모아 같은 부분 파서로 읽었다. 새로 캡처한 서울 화면, 읽기 규칙은 평가 전 상태(중복 제거 규칙은 평가 후 추가, 아래 참고).

| | 화면 | 보이는 정답 카드(화면 단위) | 월세 카드 중 입력된 것 | 전체 항목 일치 / 일부 항목만 일치 | 자동 입력 면적·관리비 | 틀린 값 |
|---|---|---|---|---|---|---|
| 다방 | 24 | 480 | 394/398 (99%) | 398 / 39 | 829개 | 0 |
| 직방 | 17 | 310 | 294/300 (98%) | 265 / 33 | 561개 | 0 |

- 화면 단위 집계라 겹치는 화면의 같은 카드가 중복 집계된다. 월세 고유 카드(머리줄+면적)로 세면 다방 61개 중 61개, 직방 192개 중 187개 입력(97%).
- 전세 카드는 월세 비교 대상이 아니어서 위 표에서 제외했다. 다방 화면의 17%가 전세이고 한 엔진만 읽는 경우가 많다(약 5%).
- **평가 방법의 한계:** 화면 안에 완전히 보이는 글자만 정답으로 삼았으므로 잘려 보이는 카드나 가려진 글자의 어려운 사례는 빠진다. 글자 노드 위치 기준이라 실제 픽셀에서 가려진 글자는 구분하지 못한다. 위 수치는 웹 목록 화면의 이 평가 조건에 한정되며 앱 캡처·상세 화면·사진 속 글자 성능이 아니다. 오류 0은 관측된 조건에서의 결과이며 다른 화면에서도 없다는 보장이 아니다.
- **평가 후 추가한 규칙:** 직방 조각 경계에서 잘려 머리줄만 읽힌 카드가 겹친 조각의 온전한 카드와 중복으로 나왔다. 그래서 **그 조각의 마지막 카드이고, 다른 조각에 같은 머리줄·값이 모순되지 않는 더 완전한 카드가 있을 때만** 잘린 쪽을 버린다. 같은 조각 안이나 조각 중간의 같은 머리줄 카드는 서로 다른 매물일 수 있어 합치거나 버리지 않는다(시험 있음). 이 규칙은 평가 결과를 본 뒤 추가했으므로 **수정된 최종 코드의 독립 검증은 아직 안 했다.** 규칙을 고치지 않은 새 화면으로 다시 평가해야 한다.
