# extraction — 광고 이미지 -> 필드 자동 입력 (로컬 시험, 팀 연동 미정)
흐름: 이미지 -> (Qwen2-VL-2B-Instruct, Apache-2.0, 무학습) 글자 전사 -> 규칙 파서(`parse_ad_text.py`)로 금액·단위·포함/별도 구조화 -> 사용자 확인 -> `utility/check.py`.
- `make_synthetic_ads.py` 합성 광고 8장+정답, `run_qwen2vl.py` 모델에 JSON을 직접 요청(실패 예: 금액 단위·자릿수 오류, 근거 환각), `run_hybrid.py` 전사+규칙 파서, `test_parser.py` 파서 검증, `pipeline_demo.py` 점검 모듈 연결.
- 모델은 `data/models/`(저장소 제외, 약 4.2GB). 합성 8장 결과는 개발용 회귀 테스트이며 실제 광고 정확도가 아니다(파서가 이 8장을 보며 만들어짐).

## 독립(held-out) 문구 12개 평가 (2026-10-20, `heldout_cases.py`, `eval_heldout.py`)
파서를 만든 뒤 따로 쓴 문구 12개(OCR 전 단계의 텍스트)로 **첫 평가**: 관리비 금액·상태·포함 항목·별도 항목은 12/12, 보증금 6/12, 월세 7/12(실패 원인: 구분자 없는 "보증금 1000 월세 55", "2천만원/5천만원" 표기, "월세 70 보증금 3000" 순서). 이후 파서를 고쳐 12/12가 되었으므로 이 12개는 **개발 데이터**로 격하됨(새 독립 평가 필요). 합성 문구이며 실제 광고 정확도가 아니다.

## 실제 다방 목록 화면 읽기 확인 (2026-10-20, `eval_real_list.py`, 캡처는 `real/`에 로컬 보관·gitignore)
- 실제 화면 한 장(1400x3600, 매물 카드 24개)을 조각내 Qwen2-VL로 전사하고 정규식으로 월세/보증금·면적·관리비를 읽어 같은 화면 DOM 텍스트와 비교.
- 처음 14/24 → 조각 겹침 확대, '월세'를 '원세'로 잘못 옮기는 전사 오류 허용, 좌표만 돌려준 조각 재시도로 **18/24**를 모든 필드 정확히 읽음. 읽은 카드 중 틀린 값은 0건, 못 읽은 6개는 누락(첫 조각 등).
- 소규모(한 화면) 확인이며 일반화 정확도가 아니다. 이 목록의 원룸(33㎡ 미만, 단기 제외, n=13) 관리비 중앙값은 8만원으로 우리 수도+전기+인터넷 참고 합계(5.2~7.8만원)와 비슷한 규모(항목별 검증은 불가: 다방 비로그인 상세에서 포함 항목 '상세보기'가 열리지 않음).
